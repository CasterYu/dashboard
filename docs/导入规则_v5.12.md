# 导入规则 · 业务数据看板 v5.12

> 三类数据导入的 Excel/CSV 列映射、工号匹配规则、拒绝条件。代码：`services/importService.js`（名册/指标）+ `services/actionScoring_v4.6.js`（评分）。

## 一、名册导入（POST /api/import/org）

**列映射**（表头）：`大区 / 小区 / 门店 / 岗位 / 人员 / 工号 / 生效日期`

**工号规则**：
- 工号列可选，但强烈建议填写（缺失降级姓名匹配并告警）
- 工号归一化：`normEmpNo`（去前导零/空格）
- 一码多人检测：同一工号对应多个姓名 → 拒绝该行

**人员定位优先级**：工号精确 → 岗位+姓名 → 门店+姓名（仅无工号者）→ 新建

**mode**：
- `merge`（默认）：只新增与调岗，不做离职判定
- `snapshot`：以文件涉及大区为范围，名单外节点停用、重新出现恢复；有安全阀（停用占比>20% 拦截）

**调岗**：关闭旧任职段（生效日前一日）+ 开新段 + 迁移节点，历史按当时架构归属

## 二、指标导入（POST /api/import/metrics）

**列映射**：`日期 / 门店 / 人员 / 岗位 / 工号` + 11 项指标（线索量/有效线索/意向线索/邀约排程/到店量/有效试驾/试驾点评数/二次回访/商机量/锁单量/交付量）

**定位规则**：
- 有工号 → 按工号精确定位（未匹配则拒绝：需先导名册）
- 无工号 → 门店+姓名（门店必填），岗位列可选（填了则必须与人员岗位一致）

**写入**：同人同日覆盖（`ON CONFLICT(person_id,date) DO UPDATE`）

## 三、评分导入（POST /api/import/scoring）

**两个 sheet**：
- **明细 sheet**（第 3 行起）：`店名(0) / 专营店编码(1) / 姓名(3) / 工号(4) / 日期(5) / 拿分项(6) / 动作(7) / 得分(8) / 证据(9) / 订单号(11)`
- **汇总 sheet**：`店名/编码/姓名/工号/日期/拿分项/目标/数量/目标分/得分`

**岗位识别**：Excel 无岗位列，由脚本硬编码（productExpert/deliveryManager/deliverySpecialist/dataExpert/newMedia）

**门店归属（orgMap 模式）**：按「专营店编码」匹配映射表 → 幂等建大区/小区/门店树；未命中编码默认跳过（import-all 挂「其它/未匹配」）。交付店长/专员编码为 DMS 数字编码，靠 `augmentMapByName` 按店名别名对齐。

**工号规则（v5.12 起）**：
- **有工号 → 实名通道**（按 emp_no 查人员，查不到则创建实名人员）
- **无工号 → 拒绝导入**（`personOf` 返回 null，`rejectedNoEmp` 统计），**不再生成 `[岗位名]店名` 虚拟人物**

**写入**：`action_scores`（明细，UNIQUE(person_id,date,item,action,order_no)）+ `action_daily_sums`（日汇总，PRIMARY KEY(person_id,date,item)）+ `import_logs`（留痕回滚）
