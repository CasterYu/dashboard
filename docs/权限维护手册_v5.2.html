权限维护手册 v5.2

适用版本：看板 v5.2（RBAC 权限树）。本手册面向管理员，不需要任何编程知识。

0. 三层入口，按能力选

层级形态适合谁
① 交互菜单（主推）双击 权限管理_v5.2.bat → 中文菜单 → 按数字选 → 按提示输入完全不懂命令行的人
② 单条命令node scripts\manage-scope_v5.2.js set --emp E90001 --nodes "A大区/a小区"会复制粘贴的人
③ HTTP 接口PUT /api/admin/users/E90001/scope-nodes以后接前端管理页/其他系统

三层入口最终都写同一张授权表，效果完全一致。改完即时生效：被改的人刷新看板页面即可（无需重新登录、无需重启后端）。

1. 核心概念（3 句话）

  • 角色回答"你能用哪些功能"（总部管理员/大区总监/店长/员工/自定义督导…）
  • 授权回答"你能看哪片数据"（哪个大区/小区/门店，可跨大区、可混合层级、可整体给但抠掉局部）
  • 组织树只是公司结构，改授权不动组织树，动的是授权表里的几行数据

2. 交互菜单长什么样

══════════ 业务数据看板 · 权限管理 v5.2 ══════════ 当前账号库: 5 个账号, 5 个角色 请选择操作： 1. 查看某人的管辖范围 2. 给某人分配管辖范围（新建/整体替换） 3. 追加授权（在他现有范围上增加） 4. 收回部分授权 5. 清除全部授权（恢复"按组织结构自动算"） 6. 查看全部账号权限一览表 7. 角色管理（查看/新增/删除自定义角色） 0. 退出 请输入数字：2 请输入工号（输 0 返回）: E90001 请输入管辖节点（多节点用逗号分隔，如 A大区/a小区, A大区/c小区/门店三）: A大区/a小区 是否有排除节点？（直接回车=无；如 A大区/b小区）: A大区/b小区 ✓ 已生效： 数据范围: a小区（除 b小区） 该用户下次刷新看板即为新范围（无需重登、无需重启后端）

节点怎么写

像文件夹路径一样用斜杠从大到小写：A大区/a小区/门店一。可以只写到任意一层（只写 A大区 = 整个大区）。写错了系统会列出同层级的正确名称供你复制。中英文逗号都可以分隔多个节点。

3. 常见维护场景

场景 A：新来的负责人接手一半辖区（a、b 小区）

菜单选 2 → 工号 → 输 A大区/a小区, A大区/b小区

场景 B：负责人管整个大区，唯独 b 小区归别人

菜单选 2 → 工号 → 输 A大区 → 排除项输 A大区/b小区

用"排除"的好处：以后 b 小区下面新开门店，自动不归他管，不需要回头改配置。

场景 C：临时把别的大区一家门店划给他兼管（跨大区）

菜单选 3 → 工号 → 输 B大区/e小区/门店四

系统不限制"授权必须在本人大区内"，编制与管辖彻底解耦。

场景 D：某人调岗/离职

菜单选 5（清空授权，回到按新组织位置自动算）或选 4（只收回某部分）

场景 E：业务要一个"督导"角色（能看数据，无管理功能）

菜单选 7 → a → code: supervisor → 显示名: 督导 → 层级: 小区 → 权限点: 回车（默认仅看板查看）

然后用 npm run users add 工号 supervisor 建账号绑角色，再回菜单 2 配管辖范围。

场景 F：怎么确认改对了

菜单选 1 看某人范围（含覆盖节点数）；或选 6 看全员一览表

4. 命令行速查（②层入口）

node scripts\manage-scope_v5.2.js list node scripts\manage-scope_v5.2.js list --emp E90001 node scripts\manage-scope_v5.2.js set --emp E90001 --nodes "A大区/a小区" --exclude "A大区/b小区" node scripts\manage-scope_v5.2.js add --emp E90001 --nodes "B大区/e小区/门店四" node scripts\manage-scope_v5.2.js remove --emp E90001 --nodes "A大区/a小区" node scripts\manage-scope_v5.2.js clear --emp E90001 node scripts\manage-scope_v5.2.js role list node scripts\manage-scope_v5.2.js role add supervisor 督导 --level 小区 --perms dashboard.view node scripts\manage-scope_v5.2.js role del supervisor

（在 D:\projects\dashboard\server 目录下执行）

5. 接口速查（③层入口，供后续接 UI）

接口说明
GET /api/admin/users/:empNo/scope-nodes查看某人授权与当前范围
PUT /api/admin/users/:empNo/scope-nodes整体替换；body: {"nodes":[{"path":"A大区/a小区"},{"path":"A大区/b小区","mode":"exclude"}]}
POST /api/admin/users/:empNo/scope-nodes追加授权，body 同上
DELETE /api/admin/users/:empNo/scope-nodes清空授权，回到自动派生
GET/POST /api/admin/roles、PUT/DELETE /api/admin/roles/:code角色 CRUD（内置角色禁删禁改层级）

须带 Authorization: Bearer <token>；仅 hq 账号或持有 admin.userManage / roles.manage 权限点的角色可调。

6. 安全规则（系统自动强制，无需记忆）

  • 倒挂拦截：店长只能被授"门店"及以下节点，授小区/大区会被拒绝并给出中文解释
  • 权限闸：接口与脚本管理仅 hq（或有 admin.userManage 权限的角色）可操作
  • 全程留痕：所有变更追加到 server\logs\scope_changes_v5.2.log（时间+操作+工号+节点），出问题可查账
  • 排除节点有效性：排除节点不在任何管辖子树内时给警告（不阻断）

7. 常见问题

现象原因处理
改完没生效用户页面还开着刷新页面即生效（无需重登、无需重启后端）
提示"找不到节点：A大区/xx小区"名称打错或层级跳跃系统会列出该层级现有名称，复制正确写法
某人什么都看不到管辖节点被清空但仍有排除项菜单选 5 全清重来
想恢复 v5.1 老行为（按组织位置自动算）—菜单选 5 清掉该人全部授权
菜单打不开Node 环境问题确认 C:\Users\Administrator\.workbuddy\binaries\node\versions\22.22.2-2\node.exe 存在

版本说明：v5.2 起"角色"（功能权限）与"授权"（数据范围）彻底解耦。存量账号在未配置显式授权前，行为与 v5.1 完全一致（按人员在组织树上的位置自动派生范围）。
